## Changesets 使用完整流程

### 1. 安装

```bash
pnpm add -D @changesets/cli -w   # -w 表示安装到 workspace 根目录
pnpm changeset init
```

初始化后会生成：
```
.changeset/
  config.json   ← 配置文件
```

---

### 2. config.json 关键配置

```json
{
  "$schema": "https://unpkg.com/@changesets/config/schema.json",
  "changelog": "@changesets/cli/changelog",
  "commit": false,
  "linked": [],
  "access": "restricted",     // 改成 "public" 如果是公开包
  "baseBranch": "main",
  "updateInternalDependencies": "patch",
  "ignore": []
}
```

---

### 3. 日常开发流程

#### 第一步：写代码，完成后记录变更意图

```bash
pnpm changeset
```

会进入**交互式问答**：

```
# 1. 选择哪些包发生了改动（空格选中，回车确认）
Which packages would you like to include?
  ◯ @myapp/core
  ◯ @myapp/utils
  ◉ @myapp/ui       ← 选这个

# 2. 选择版本级别
What kind of change is this for @myapp/ui?
  ○ patch   (bug fix, 1.0.0 → 1.0.1)
  ● minor   (new feature, 1.0.0 → 1.1.0)
  ○ major   (breaking change, 1.0.0 → 2.0.0)

# 3. 填写描述（会进入编辑器）
Please enter a summary for this change
> Add dark mode support
```

执行后生成一个 changeset 文件：

```
.changeset/
  fuzzy-dogs-dance.md    ← 随机命名
```

文件内容：
```markdown
---
"@myapp/ui": minor
---

Add dark mode support
```

#### 第二步：把这个文件连同代码一起提交

```bash
git add .
git commit -m "feat: add dark mode to ui"
```

> 这个 `.md` 文件就是"发布意图的凭证"，PR 里要带上它。

---

### 4. 发布流程

#### 第一步：版本消费（更新所有 package.json）

```bash
pnpm changeset version
```

Changesets 会：
- 读取所有 `.changeset/*.md`
- 自动计算每个包的新版本
- 更新各包的 `package.json`
- 更新依赖该包的其他包的版本号
- 生成 / 更新每个包的 `CHANGELOG.md`
- **删除已消费的 changeset 文件**

```
packages/
  ui/
    package.json    ← version: "1.0.0" → "1.1.0"
    CHANGELOG.md    ← 自动追加本次变更记录
```

#### 第二步：发布到 npm

```bash
pnpm changeset publish
```

会对所有版本有变动的包执行 `npm publish`，并自动打 git tag。

---

### 5. 完整工作流汇总

```
开发功能
   ↓
pnpm changeset          # 记录变更意图（生成 .md 文件）
   ↓
git commit + push       # .md 文件跟代码一起提交，合入主分支
   ↓
pnpm changeset version  # 消费所有 .md，更新版本号和 CHANGELOG
   ↓
git commit              # 提交版本变更
   ↓
pnpm changeset publish  # 发布到 npm + 打 tag
```

---

### 6. 配合 CI 自动化（GitHub Actions）

实际项目中发布步骤通常交给 CI，用官方的 `changesets/action`：

```yaml
# .github/workflows/release.yml
name: Release

on:
  push:
    branches: [main]

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v2
      - uses: actions/setup-node@v4

      - run: pnpm install

      - name: Create Release PR or Publish
        uses: changesets/action@v1
        with:
          publish: pnpm changeset publish
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          NPM_TOKEN: ${{ secrets.NPM_TOKEN }}
```

这个 Action 的行为：
- 若检测到未消费的 `.md` 文件 → 自动创建"Version Packages" PR
- 若该 PR 被合并 → 自动执行 publish

整个流程就变成：**开发者只需跑 `pnpm changeset`，其余全自动**。
