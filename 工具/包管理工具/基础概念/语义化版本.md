## 语义化版本（Semantic Versioning）

版本号格式是 `主版本.次版本.修订版本`，即：

```
    1  .  2  .  3
  major minor patch
```

---

### 三种类型的含义

#### patch — 修订版本（1.0.0 → 1.0.1）
**修了 bug，没有新功能，用法完全不变。**

```js
// 修复前：某些情况下返回 undefined
function getUser(id) { ... }

// 修复后：正常返回
function getUser(id) { ... }
```

用户升级后**不需要改任何代码**，只是之前的 bug 没了。

---

#### minor — 次版本（1.0.0 → 1.1.0）
**加了新功能，但旧功能完全不受影响。**

```js
// 原来只有这个
function getUser(id) { ... }

// 新增了这个，旧的没动
function getUserByEmail(email) { ... }
```

用户升级后**不需要改任何代码**，但可以选择使用新功能。

---

#### major — 主版本（1.0.0 → 2.0.0）
**有破坏性变更（Breaking Change），旧代码可能跑不起来。**

```js
// v1：接收 id
function getUser(id) { ... }

// v2：改成接收 options 对象，旧的调用方式直接报错
function getUser({ id, fields }) { ... }
```

用户升级后**必须修改代码**才能正常运行。

---

### 一句话记忆

| 类型 | 改了什么 | 用户需要改代码吗 |
|------|---------|--------------|
| patch | 修 bug | ❌ 不需要 |
| minor | 加功能 | ❌ 不需要 |
| major | 破坏性改动 | ✅ 必须改 |

> 规则就是：**能不升 major 就不升**，让使用者平滑升级。
